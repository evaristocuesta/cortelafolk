# AGENTS.md

Static Astro 7 + Tailwind CSS 4 site (Spanish) for the Cortelafolk 2027 festival. No client framework, no backend, no API. pnpm, Node >= 22.12.

The public pages are `src/pages/index.astro` (minimal root teaser), `src/pages/ediciones/index.astro` (the archive of past editions: three posters plus the selected photographs of each year — 25 in 2024, 54 in 2025, 32 in 2026), `src/pages/cookies.astro` and `src/pages/privacidad.astro` (legal policies), and `src/pages/2027/index.astro` (full festival site, still served at `/2027/` while it's being built out). `src/pages/404.astro` is the Spanish not-found page served as `dist/404.html`.

## Commands

- `pnpm install`
- `pnpm dev --background` — managed dev server. Then `pnpm astro dev status` / `logs` / `stop`. A foreground `pnpm dev` blocks the session; prefer background mode.
- `pnpm check` — Astro + TypeScript diagnostics. This is the only static check; there is no lint or format script.
- `pnpm images` — regenerate `public/images/<year>/*.webp`, the `-thumb.webp` crops and `src/data/edition-images.json` from `originals/ediciones/<year>/`. It uses `sharp` (and `heic-convert` for the iPhone originals), starts at WebP quality 80 and steps down only when a photograph would exceed the byte ceiling. Run it after changing the numbered originals.
- `pnpm build` then `pnpm test` — **build first**: the tests read the built pages under `dist/` (`index.html`, `2027/index.html`, `ediciones/index.html`, `cookies/`, `privacidad/`) and fail with "Run pnpm build before pnpm test."
- Single test: `node --test --test-name-pattern="…" scripts/site.test.mjs` (the flag must precede the file path).

Verify a change with `pnpm check && pnpm build && pnpm test`.

## What `pnpm test` actually pins

`scripts/site.test.mjs` is a contract test against the **built** HTML/CSS, not unit tests. Most assertions target the full festival contract at `/2027/`; a smaller set covers the root landing page. It asserts:

- root landing page (`dist/index.html`): the Cortelafolk logo, the 2027 dates and location, an `ENTRADA LIBRE` mention, exactly one `<h1>`, and a title mirrored by `og:title` / `twitter:title` (`Cortelafolk 2027 · Festival de folk en Cortelazor · 23–25 abril`).
- landing structured data (only when `PUBLIC_SITE_URL` is set): a `MusicEvent` JSON-LD with the approved facts (dates, Cortelazor, free access, `inLanguage: es-ES`), no `offers` because the festival has no tickets or registration, no `performer` until the lineup is confirmed, and the two `organizer` names identical to the visible `#organizacion` credits. When the env is unset, the landing must emit no `ld+json` at all.
- crawl surface: `dist/robots.txt` (`Allow: /`, `Disallow: /2027/` — drop both the rule and the assertion together when the festival page goes public — and a `Sitemap:` line), `dist/sitemap.xml` listing exactly the root landing, `/ediciones/` and the public `/cookies/` and `/privacidad/` pages, and `dist/404.html` (Spanish, `noindex`, one `<h1>`, link back to `/`).
- consent: the landing, festival and legal pages install the same GTM container after setting Consent Mode defaults (`analytics_storage` denied; advertising storage denied). The banner stores necessary, statistics and external-content choices, updates the data layer via `cookie_consent_update`, and offers a persistent control to revise the choice. Analytics must remain blocked until statistics consent. The Google Maps iframe is not requested until external content is accepted or the visitor explicitly loads it once.
- festival page (`dist/2027/index.html`): exact Spanish copy, exact section IDs (`home`, `festival`, `artistas`, `free-access`, `programacion`, `actividades`, `como-llegar`, `informacion`, `organizacion`), a single `<h1>`, exactly 10 `.section-wave` dividers, 6 `<details>`, 3 `data-schedule-day` blocks.
- schedule: 16 slots, each naming one of the four stages (concerts in the plaza or the church, hands-on sessions in the museum or the hall, all four stages used, stage strip describes all four); every slot title is either written by the schedule or borrowed from `artists.ts` / `activities.ts`, and the timetable lists each artist and each activity exactly once. The 10 catalogue-linked rows are buttons opening the same profile modal as their card with an identical payload; cards and modals show the `HH:MM · Stage` line from `artistSlot` / `activitySlot` / `slotLabel`; both modals are rendered from the shared `ProfileDialog.astro` (a test asserts the two dialog blocks are structurally identical).
- every `href` on the built content and legal pages resolves: anchors to an existing `id`, local paths to a file in `dist/`, external links to `https://` (no local origins).
- previous editions (`dist/ediciones/index.html`): one `<h1>`, the `2024/2025/2026 · N.ª edición` labels, exactly 3 poster links sharing `data-group="carteles"` and one photo link per file in `src/data/edition-images.json` (25/54/32) across `galeria-<year>`, every grid image loading its 600×400 `-thumb.webp` crop while the link opens the 1600 px file, every image with `alt` plus `width`/`height`, and no link out of its own `/images/<year>/` folder. The archive must never link to `/2027/` (a test pins that, along with the landing page's link into `/ediciones/`).
- archive head: the same gate as the other pages. With `PUBLIC_SITE_URL` set it emits the canonical URL, the shared 1200×630 `social-preview.png` as `og:image` / `twitter:image` (with Spanish alt text) and a `CollectionPage` JSON-LD — `inLanguage: es-ES`, `isPartOf` the `WebSite`, `about` a `MusicFestival` in Cortelazor, and one `ImageGallery` per edition pointing at its `#edicion-<year>` anchor with the poster as `image`. It carries no `startDate`/`endDate` (the posters are the only source of past dates) and no `/2027/` URL. Unset, the page emits no absolute URL and no JSON-LD at all.
- archive separators: exactly 4 thick moss `WaveDivider` tapes on `/ediciones/` — under the menu, after the posters, and between 2024/2025 and 2025/2026; the last gallery keeps the footer's rule instead. The archive sections are full-width direct children of `<main>` (the shared `main > section` rule positions the tapes) and the header carries `relative`; the old `border-t` gallery rules and the header's `border-bottom` are gone, and the posters heading owns the `posters-title` id its section references.
- archive viewer: exactly one `<dialog data-lightbox>` with Spanish `aria-label` and prev/next/close buttons, one trigger per poster and per photograph (114 today) that are plain `<a href>` images (progressive: they still open the file without JS), and `src/scripts/lightbox.ts` answering `ArrowLeft` / `ArrowRight`, Escape, backdrop clicks and horizontal touch swipes (pointer events, `pointerType` touch/pen only, >40px and clearly horizontal; `touch-action: pan-y` on the media cell keeps vertical drags as scrolls) with a "N de M" counter. The swipe is a real carousel animated with the Web Animations API: the media cell holds a window (`.editions-lightbox-viewport`, `overflow: hidden`, one cell) around a strip of three cells (`data-lightbox-neighbor="prev"`, `data-lightbox-image`, `data-lightbox-neighbor="next"`, offset `±(100% + var(--editions-gap))` in CSS) that translates with the finger — at rest the neighbours are clipped out of sight, while dragging they slide in with a visible gap between prints. A committed swipe slides the strip by the measured stride (cell + gap, read from `getBoundingClientRect`, never duplicated in JS) with `fill: 'forwards'` and re-centres it in `exit.onfinish` (cancel + `move(0)` + `step` in one task). Re-centring **rotates the roles** of the three `<img>` elements (`setRole` moves `data-lightbox-image` / `data-lightbox-neighbor`) instead of rewriting the centre's `src`: the incoming cell keeps its decoded bitmap, which is what prevents a one-frame flash of the previous photograph; only the far, off-screen cell is repainted. Buttons and keys go through `go()` so a second press cannot stack animations mid-slide. A short drag settles back, and `prefers-reduced-motion: reduce` drops all of it while keeping the navigation. Neighbours are painted from their own triggers on open and all three srcs are released on close. The media cell must stay a **flex** line: the strip is its flex item with `width/height: 100%` (a grid item's auto row leaves the percentage height unresolved, so a tall poster paints at natural size and gets clipped), and each photograph fills its cell with `object-fit: contain` (verified in headless Chrome at desktop and narrow widths; a test pins the rules).
- asset budgets: total client JS (bundled + **deduplicated** inline) < 12 KB — shared boilerplate (consent banner, Consent Mode defaults) is counted once across pages — each `-thumb.webp` < 200 KB, each full 1600 px archive photograph < 420 KB (quality 80 by default, stepped down only when a detailed scene would exceed the ceiling), every other `.webp` under `dist/images/` < 200 KB (the budget walks subfolders), `social-preview.png` exactly 1200×630, every `src`/`href` root-absolute path present in `dist/` (URL-encoded names are decoded before lookup).
- generated Tailwind selectors (`.tablet\:grid-cols-4`, `.wide\:px-16`, `.aria-pressed\:bg-forest`, `.group-open\:rotate-45`) and `scroll-padding-top` 82 / 72 / 68 px at the three breakpoints.
- no `<form>` or ticketing wording (consent checkboxes are allowed), no `class="is-active"`, no localhost canonical/`og:url` when `PUBLIC_SITE_URL` is unset.

Renaming an ID, changing visitor-facing copy, adding a section, or swapping an image means updating this test in the same change.

## Content rules

- Visitor-facing text, alt text and interaction states are **Spanish**; technical identifiers, section anchors and documentation are **English**.
- Artist names, times, stages and activities are **fictional placeholders**; the "orientativa" / "Cartel en preparación" notices were removed on purpose, so don't re-add them, and never phrase invented details as confirmed. Approved facts only: fourth edition, 23–25 April 2027, Cortelazor (Huelva), free access without tickets or registration. Don't invent sponsors, contact details or social profiles.
- The archive is the organiser's numbered selection: 25 photographs for 2024, 54 for 2025 and 32 for 2026. The full-resolution originals live in `originals/ediciones/<year>/` (gitignored); `pnpm images` reads them in natural filename order, writes one 1600 px WebP plus a 600×400 `-thumb.webp` per photograph, and regenerates `src/data/edition-images.json` with the file names, dimensions and byte counts. Do not edit that generated file by hand. The Spanish `alt` text lives in `src/data/edition-alts.json`, keyed by `year/file`: one coarse category (`Puestos de artesanía`, `Concierto`, `Talleres y actividades`, `Juegos de mesa`, `Asistentes del festival`) followed by `Cortelafolk <year>.`; classify each new photograph the same way (the fallback is generic). Gallery captions carry only the year and edition number (`2025 · 2.ª edición`); never add dates or facts the posters don't state. Do not rename or move files under `public/images/2024|2025|2026` or `originals/ediciones` without re-running `pnpm images`.
- The `#organizacion` section ships **real organisers** (La mano verde, Ayuntamiento de Cortelazor) and **placeholder collaborators** (Colaborador 1–20 pointing at `*.com` domains) on purpose; each entry in `organizers` / `collaborators` in `src/data/site.ts` carries its own `logo` path under `public/images/partners/`, meant to be swapped for the real links and logos. The `organizers` array also feeds the landing `MusicEvent` JSON-LD, so keep both in sync by editing only that array. The user has supplied La Mano Verde as the privacy-policy controller name and `arte@lamanoverde.info` as contact; do not infer missing legal identifiers or addresses.

## Styling

- Tailwind utilities directly in Astro components for layout; `src/styles/global.css` holds poster composition, illustrations, decorative pseudo-elements and shared editorial typography. Don't express everything as arbitrary utilities, and don't duplicate a rule in both places.
- Custom breakpoints live in `@theme`: `tablet` = 60rem (960px), `wide` = 68.8125rem (1101px). Define new breakpoints and min-width variants in **rem** so they sort with Tailwind's defaults.
- Use `PageContainer.astro` for page widths; never add a global `.container` (it collides with Tailwind's utility).
- Schedule filters use `aria-pressed:` variants as the sole active-state source; FAQs are native `details` driven by `group-open:`. Preserve the global `[hidden]` rule and reduced-motion overrides.

## Config and deployment

- Canonical URL, absolute social image URLs and JSON-LD are emitted only when `PUBLIC_SITE_URL` is set at build time (`src/pages/index.astro` and `src/pages/2027/index.astro` for the 2027 `MusicEvent`; `src/pages/ediciones/index.astro` for its canonical/`og:url`, the shared social card and the archive's `CollectionPage`; see `.env.example`). Never build with a localhost origin. `public/robots.txt` and `public/sitemap.xml` hardcode the production origin (they are static files); the sitemap lists the root, `/ediciones/` and the public legal policies, and `robots.txt` currently disallows `/2027/` until the festival page is published. The `/ediciones/` page carries its own minimal header/footer and no `SiteHeader` on purpose: nothing public may link into `/2027/` before the 2027 poster is announced.
- `dist/` is gitignored build output — that's what gets uploaded to a static host.
